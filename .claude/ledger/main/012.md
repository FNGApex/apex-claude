## Goal

From: user (via a non-Apex session in ~)

Let each Apex Agent carry its own Claude Code theme, so starting `/<agent>` switches the Claude Code UI colors to
that Agent's theme. It must be per repo and per Agent: `/dev` in repo A and `/dev` in repo B can have different
themes.

Done when:
- A mod that sets the theme when an Agent's role card runs ships in apex-claude and is installed by `make install`
  (and `scripts/install.ps1`) and removed by `make uninstall`, under the same never-touch-what-we-didn't-install rule.
- Where the theme for an Agent is declared is decided and documented in README.md and docs/design/agents.md;
  `/apex-init` writes it, or says where to, when it creates a role card.
- Verified in a live session: starting an Agent switches the theme; an Agent without a theme leaves it alone.
- `claude plugin validate <mod folder>` passes.

Prototype, working but not yet run live: `~/.claude/mods/skill-themes/` (in the user's local marketplace
`~/.claude/mods/.claude-plugin/marketplace.json`, not installed yet). It reads `<repo>/.claude/skill-themes.json`,
for example `{ "dev": "custom:dev", "default": "dark" }`. On `session.start` it sets `default`. On `skill.prompt`
it sets the entry for `e.skill`. The setting is changed with `$.config.set({ key: "theme", value })`, and a denial
is shown as a toast.

Design choice (the user has not picked one; ask before building):
- Recommended: a `theme:` key in the role card's frontmatter (`.claude/skills/<agent>/SKILL.md`). The
  `skill.prompt` event carries it as `e.frontmatter`, so no JSON file is needed and it is per repo for free. Check
  `e.source` (`projectSettings`) so only repo skills can switch it.
- Alternative: keep `.claude/skill-themes.json` as the prototype does.

Risks to check first:
- `$.config.set` is refused for "a row only its dialog changes". It is not documented whether `theme` is such a
  row. Test this first; if it is refused, fall back to a shell alias,
  `claude --settings '{"theme":"custom:<agent>"}' "/<agent>"`.
- `config.set` persists like a `/config` change, so the theme outlives the session. Decide on a reset: a
  `default` on `session.start`, or none.
- `skill.prompt` also fires on preloads (the Skill tool, `agent-protocol` and so on). Only skills mapped to a theme
  should switch it.

References: custom themes are `~/.claude/themes/<slug>.json` (`name`, `base`, `overrides`), stored as
`custom:<slug>` (https://code.claude.com/docs/en/terminal-config.md). The mod API types are written by the
`plugin-authoring` skill when it loads; grep them for `'skill.prompt'` and `config: {`.
